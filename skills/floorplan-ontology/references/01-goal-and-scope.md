# 목표와 범위

## 문제 정의

SVG 평면도는 시각적으로는 풍부하지만, 대부분의 정보가 도형과 텍스트로 분산되어 있다. 방 이름, 치수, 문, 창문, 벽, 설비, 외부 공간, 동선은 모두 사람이 보면 이해할 수 있지만, SVG 자체에는 이들이 명시적인 데이터 객체로 존재하지 않는다.

이 프로젝트의 목표는 SVG 평면도를 다음과 같은 구조화 데이터로 전환하는 것이다.

- 라벨 추출
- 벡터 노드 추출
- 공간 및 구조 entity 생성
- entity 간 관계 그래프 생성
- 동선, 통풍, 채광, 기능성 분석의 기반 생성
- 장기적으로 온톨로지 또는 knowledge graph로 확장

## 최종 목표

최종 목표는 단순히 `LIVING ROOM`, `KITCHEN` 같은 방 이름을 뽑는 것이 아니다. 목표는 공간을 구성하는 요소와 그 관계를 기계적으로 해석 가능한 형태로 만드는 것이다.

```text
무엇이 있는가
 -> 어디에 있는가
 -> 무엇과 연결되는가
 -> 어떻게 사용할 수 있는가
 -> 구조적으로 어떤 의미가 있는가
```

## 핵심 질문

처리 시스템은 최종적으로 다음 질문에 답할 수 있어야 한다.

- 이 도면에는 어떤 공간이 있는가?
- 각 공간의 라벨, 치수, 면적, 위치는 무엇인가?
- 어떤 벡터 도형이 어떤 공간이나 구조물을 구성하는가?
- 방과 방은 어떤 문이나 개구부로 연결되는가?
- 벽, 문, 창문은 각각 어느 공간에 속하거나 접해 있는가?
- 문은 어느 방향으로 열리고, 열렸을 때 동선을 방해하는가?
- 창문은 어느 벽에 있고 외부와 접하는가?
- 어떤 공간이 자연광을 받을 가능성이 높은가?
- 어떤 공간 사이에 통풍 경로가 형성될 수 있는가?
- 현관, 복도, 주요 생활 공간 사이의 동선은 편리한가?

## 범위

### 1단계 범위

1단계는 SVG를 안정적으로 구조화하는 데 집중한다.

- SVG 파싱
- 스타일과 transform 정규화
- 텍스트 라벨 추출
- 벡터 노드 추출
- bbox, centroid, area, length 계산
- 라벨과 공간 후보 매칭
- 공간, 벽, 문, 창문, 설비 후보 생성
- 검증용 overlay 생성

### 2단계 범위

2단계는 topology를 구성한다.

- 공간 인접 관계
- 문과 공간 연결 관계
- 창문과 벽, 공간, 외부 관계
- 벽과 공간 경계 관계
- 설비와 공간 포함 관계
- 복도와 circulation space 추론

### 3단계 범위

3단계는 기능적, 구조적 분석이다.

- 동선 분석
- 문 개폐 방향과 충돌 분석
- 창문 배치 분석
- 통풍 가능성 분석
- 채광 가능성 분석
- 공간 기능성 평가
- 프라이버시와 접근성 평가

## 비목표

초기 단계에서 다음은 목표가 아니다.

- 완전한 건축 법규 검토
- 실제 물리 시뮬레이션 수준의 채광 분석
- CFD 수준의 통풍 해석
- 사람이 검증하지 않아도 되는 완전 자동 온톨로지 생성
- 모든 SVG 벤더 형식에 대한 일반화

초기 목표는 한 파일에서 신뢰 가능한 중간 표현을 만들고, 이후 여러 SVG로 확장 가능한 규칙과 검증 구조를 확보하는 것이다.

## 성공 기준

초기 MVP의 성공 기준은 다음과 같다.

- 모든 SVG 도형이 stable id를 가진 `VectorNode`로 추출된다.
- 모든 텍스트 라벨이 `LabelEntity`로 추출된다.
- 방 이름과 치수가 분리된다.
- 주요 공간 entity가 생성된다.
- 라벨과 공간 후보가 연결된다.
- 문, 창문, 벽 후보가 별도 카테고리로 분리된다.
- 추출 결과를 SVG 위에 overlay해서 사람이 검증할 수 있다.
- 불확실한 판단은 명시적으로 표시된다.
